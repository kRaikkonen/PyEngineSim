# EngineSim v2 core

One compiled core, written once (Rust), used by the phone, the desktop studio and the tests alike.
The design is `docs/REDESIGN_V2.md`; this is stage **S1** of it: the single firing event.

| | |
|---|---|
| `sound/` | the real-time sound model. So far: the cylinders — each one's gas solved live, its valves' flow in kg/s |
| `capi/` | the C ABI (`include/enginesim_core.h`), built as a DLL / dylib and a static library |
| `../engine_sim/corelib.py` | Python's door into it (ctypes) |
| `../engine_sim/core_spec.py` | the bake side: an engine preset → the core's spec |

No external crates: the build needs only the Rust toolchain.

## Build and test

```bash
cargo test --release
```

```bash
cargo build --release
```

```bash
python ../tools/core_check.py
```

- `cargo test` — the model against closed forms (adiabat, choked blowdown), its own conservation of mass
  and energy, a racing head's overlap, block-length independence, and "the render path never allocates".
- `tools/core_check.py` — the core against the same equations integrated independently in Python
  (it must converge on them, first order in the time step), and against `gas_truth.py`.

```bash
cargo run --release --example event
```

```bash
cargo run --release --example bench
```

`event` prints what one exhaust event looks like across speed and load; `bench` what the cylinders cost.

## What is in `sound` so far

- `gas.rs` — the gas (γ falls with temperature) and the compressible orifice, choked below the critical
  pressure ratio. The flow function is a polynomial fit of the isentropic law (`nozzle_fit.rs`, generated by
  `tools/gen_nozzle_fit.py`, accurate to 3e-9), so the innermost function has no powers in it.
- `cylinder.rs` — one cylinder: piston work, a Wiebe burn, Hohenberg wall heat, and both valves, with the
  valve step solved implicitly so a small volume between two open valves cannot ring. A port may be a plenum
  or a pipe (`p = p_in + z·q`) — the seam the exhaust network (S2) attaches to.
- `engine.rs` — the crank and the cylinders on it; the operating point is read every 32 samples and ramped.
- `control.rs` — the operating point, and the lock-free mailbox it crosses threads in.
- `math.rs` — `exp`, `ln`, `sin`/`cos` written here as plain arithmetic: the same bits on every platform.

## Not here yet

The pipes. `es_render` radiates the bare exhaust-valve flow as a monopole so the path can be tested end to
end; it is not what an engine sounds like. The exhaust network is stage S2.
